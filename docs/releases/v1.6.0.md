# TensorNote v1.6.0 — Distribution & Ecosystem Hardening

状态：发布基础设施与源码阶段完成；正式 Git Tag、公开 GitHub Release 和签名安装包等待 Apple Developer ID / Windows 代码签名凭据。

## 新增能力

- 标签驱动 Release Workflow 对版本、测试、性能、依赖审计、Workspace/课程模板、Static 边界和发布说明执行统一门禁。
- 同一候选构建 GitHub Pages、Web archive、macOS Apple Silicon/Intel、Windows x64 与 Linux x64，并保留容器构像验证。
- Desktop Settings → About 提供显式检查、下载、签名验证、安装和重启更新流程；Web 仍由部署渠道更新，不加载 Native Updater。
- Tauri Release 构建生成签名 Updater artifacts；Updater 公钥固定在应用中，私钥与密码已独立保存在维护者本机安全目录、macOS Keychain 与 GitHub Secrets。
- 所有候选资产生成 `SHA256SUMS` 和 `release-manifest.json`，记录版本、Tag、commit、大小与 SHA-256。
- 新增课程 Workspace 模板、Workspace v1 兼容性徽章、分发矩阵、签名验证和回滚手册。

## 候选稳定性与智能体接口补强

- 白色与淡绿工作台、统一侧栏标题和明暗选中态，标签栏居中、多标签自动定位及小窗口分栏切换。
- 命令面板、设置和文件操作共享弹窗焦点管理；文件菜单避免滚动裁切，支持键盘选择与安全的弹窗交接。
- 上下文栏宽屏停靠、窄屏抽屉；修复重复图谱、目录锚点不稳定、分栏同名标题定位和原生文件新建的缺失错误识别。
- 同版本 `TensorNote-agent-skill-X.Y.Z.tar.gz` 分发包，提供跨智能体维护规范、模板、锁定依赖和版本化 JSON 校验结果。真实 YAML、路径边界、别名、前置关系与链接检查覆盖常见生成和维护错误。

## 安全边界

- Tag 发布缺少 Apple、Windows 或 Updater 任一签名凭据时直接失败，不发布“看似正式”的未签名 Desktop 安装包。
- macOS 使用 Developer ID Application 与 Apple 公证；Apple Development identity 不满足公开分发门。
- Windows 证书只在临时 Runner Certificate Store 中导入；临时 Tauri override 只包含 Thumbprint、SHA-256 和 HTTPS timestamp，不包含 `.pfx` 或密码。
- Updater 只访问 GitHub Release HTTPS endpoint，并验证内置 minisign 公钥。Static Web build 继续拒绝 Tauri IPC、Updater 和 Native Runtime 代码泄漏。
- Release 先创建为 Draft；签名、校验值和端到端矩阵检查全部通过后才人工公开。

## 模板与生态

- 通用 Workspace 模板继续保持最小、不可执行默认值。
- 课程模板提供首页、概念、前置关系、复习问题与两个共享状态的标准库 Python Cell；它仍是普通 Markdown Repository。
- Pages Workflow 模板固定 `v1.6.0` Runtime，避免公开知识库随 `main` 漂移。
- 公开目录只完成元数据索引边界决策，本版本不引入中心化账号、内容镜像、Token 托管或公共 GPU。

## 验收与剩余外部门

源码验收包括 `pnpm check`、性能门、生产依赖审计、Local/Static/Desktop Web 构建、Rust fmt/clippy/test、两套 Workspace 模板严格校验、发布检查和无 Tag Release Workflow 演练。

正式发布仍需要维护者提供：

1. Apple Developer ID Application `.p12`、证书密码、Apple ID 公证凭据和 Team ID；
2. 受信 Windows 代码签名 `.pfx` 与密码；
3. 在无敏感日志前提下完成首次 Tag 构建并人工验证安装资产。

详细平台、资产、签名检查与回滚步骤见 [Release Matrix](../RELEASE_MATRIX.md)。在外部证书到位前不创建 `v1.6.0` Tag 或公开 Release。
