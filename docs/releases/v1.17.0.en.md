# TensorNote v1.17.0

This release redesigns environment management and Project Experiment dependency setup.

- Compute settings now start with Local or Remote runtime. Desktop provides convenient and manual local connections, Local Web provides manual local connections, and online Web only shows remote connections.
- Desktop discovers Conda from PATH and common macOS, Linux, and Windows locations and reports the executable path. Users can select a Conda or uv executable when automatic discovery fails.
- Environment creation clearly separates uv, Conda, and standard venv. Conda and uv can create Python 3.11, while venv follows the selected base interpreter. The reviewed plan shows the full target path and installation steps.
- Environment rows report the manager, exact Python version, path, Jupyter readiness, and server ownership. TensorNote only removes environments it created and that are not in use.
- The Experiment Environment tab combines manifest-declared files with `requirements*.txt` detected in the working directory. A user can install one or several files into an explicitly selected environment through a plan bound to the workspace, manifest, file digests, and target environment.
- External environments display a non-rollback warning. A failed or cancelled dependency installation keeps the existing environment and reports possible partial changes; failed new environment creation still removes the incomplete directory.

Workspace Schema v1, Workspace Provider v1, Compute Provider v1, and Project Experiment Manifest v1 remain compatible. Environment and tool paths stay in device settings and never enter the knowledge base; tokens remain session-only.
