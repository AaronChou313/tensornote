# TensorNote v1.18.0

This release reorganizes Compute & Jupyter around environments and connections.

- Desktop Local runtime starts with Python environments. Expand an environment to see kernels, its TensorNote-owned Jupyter server, logs and stop controls. A reachable owned server is reused instead of duplicated.
- Managed Environment plans show the manager, Python version, full target path, minimal notebook packages and kernel. Conda/uv can create Python 3.10–3.14; venv follows an installed interpreter.
- An external Conda/venv environment without Jupyter can receive reviewed `jupyter-server`, `ipykernel` and basic visualization support. TensorNote does not take ownership of or delete that environment.
- Local Web uses a clear manual Jupyter flow. Its folded launch command derives the allowed Origin from the current page instead of assuming a development port.
- Remote runtime is now a connection list. Generic Jupyter, JupyterHub and BinderHub details, diagnostics, lifecycle options and deletion live in a focused dialog.
- Successful diagnostics or remote startup automatically enumerate KernelSpecs, preserving the current choice or preferring `python3`. Advanced settings retain a manual override.
- Compute Store v3 persists Local/Remote classification and the last local environment. Owned-server profiles and tokens remain session-only.
- Notebook runtime dependencies are separated from optional ML examples. Project dependencies remain declared by each Workspace Project Experiment.

Workspace Schema v1, Workspace Provider v1, Compute Provider v1 and Project Experiment Manifest v1 remain compatible. Reading and editing Markdown require no Python. Execution still requires Workspace permission and fixed-revision trust for GitHub sources.
