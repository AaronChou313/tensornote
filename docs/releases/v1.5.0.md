# TensorNote v1.5.0 — Remote Compute Connectors

状态：源码阶段完成；未创建 Git Tag、GitHub Release 或签名安装包。

## 新增能力

- ComputeConnector API v1 位于 Profile 与 ComputeProvider 之间，把 Direct Jupyter、JupyterHub 或 BinderHub 统一解析为带所有权和清理语义的标准 Jupyter Connection Lease。
- Generic Jupyter 完善远程 HTTPS 与 Mixed Content 前置检查，继续只管理 TensorNote 创建的 Kernel。
- JupyterHub 使用当前用户的有限权限 API Token 自动识别身份；支持复用已有 Server、启动默认/命名 Server、消费 Progress EventStream、状态轮询回退及停止 TensorNote-owned Server。
- BinderHub 使用公开 GitHub Repository 和 40 位完整 commit SHA 调用 `/build/gh/...`，流式呈现构建阶段并把 ready 事件的临时 URL/Token 直接交给 Jupyter Provider；默认 5 分钟超时且可手动取消。
- Compute 设置增加 Connector 选择、Hub 用户与 Server、Binder 来源覆盖、生命周期开关、冷启动进度、显式启动验证和可复制无 Secret 诊断报告。
- Lab Drawer 在远程环境启动期间显示 fetching/building/launching 等状态；切换 Profile、Workspace 或关闭应用会释放当前 Lease。

## 安全与数据归属

- Hub Token 继续只保存在 `sessionStorage`；Binder 临时 Token、解析 Server URL 与 Lease 只存在运行时内存。
- Jupyter REST 请求使用 `Authorization` 头而不是 URL Query；Kernel WebSocket 连接会等待真实握手并在 10 秒后给出可操作的超时提示，避免把“已创建 Kernel”误报为“已连通”。
- Binder 必须绑定完整 commit SHA，分支或 Tag 会在任何网络请求前被拒绝。
- TensorNote 不停止连接前已经存在的 JupyterHub Server；只有本次成功启动且 Profile 允许清理的 Server 会收到 DELETE 请求。
- Remote Connector 不读取 Markdown，不自动安装 Workspace 依赖，也不绕过 Workspace execution permission 或 GitHub Revision trust。
- Binder 文件、输出和 Kernel 状态不会写回只读 GitHub Repository；持久性、费用、配额和闲置回收始终由远程服务管理者决定。
