# TensorNote v1.18.0

本版把“计算与 Jupyter”整理成以环境和连接为中心的清晰流程。

- Desktop 本地运行先展示 Python 环境；环境下展开 Kernel、Owned Jupyter Server、日志与停止操作。TensorNote 会复用同一环境中已启动且可达的自有 Server。
- 新建 Managed Environment 会显示管理器、Python 版本、完整落盘路径、最小 Notebook 包和 Kernel。Conda/uv 可创建 Python 3.10–3.14；venv 跟随已安装解释器。
- 外部 Conda/venv 缺少 Jupyter 时，可审阅独立安装计划并确认补齐 `jupyter-server`、`ipykernel` 与基础可视化包。TensorNote 不接管或删除外部环境。
- Local Web 明确采用手动 Jupyter 连接，折叠帮助中的启动命令会使用当前网页 Origin，不再固定开发端口。
- Remote runtime 改为连接列表；Generic Jupyter、JupyterHub 与 BinderHub 的复杂设置、诊断、生命周期与删除操作进入详情弹窗。
- 连接诊断或远程环境启动成功后自动枚举 KernelSpec，优先保留现有选择，其次选择 `python3`。高级设置仍可手动覆盖。
- Compute Store v3 保存 Local/Remote 分类和最后选择的本地环境；Owned Server Profile 与 Token 仍仅存在当前会话。
- Notebook 基础依赖与 ML 示例依赖分离。项目依赖继续由 Workspace 的 Project Experiment requirements 声明。

兼容性保持 Workspace Schema v1、Workspace Provider v1、Compute Provider v1 和 Project Experiment Manifest v1。阅读与编辑 Markdown 不需要 Python；代码执行仍需要 Workspace 授权，GitHub 来源还需要固定 Revision 信任。
