# TensorNote v1.3.0 — Local Runtime Assistant

状态：源码阶段完成；未创建 Git Tag 或 GitHub Release

## 本阶段交付

- Desktop 设置页新增 Local Runtime Assistant，只读发现 PATH、常见安装位置、Workspace venv、Conda 环境和 TensorNote Managed Environment 中的 Python、uv、Conda、Jupyter、Kernel 与 Loopback Server。
- 前端只接收 Opaque Tool/Environment/Plan/Server ID 与结构化健康信息，不接收可执行文件或个人目录绝对路径。
- 支持 uv、标准 venv 与 Conda 的审核式最小环境计划。用户必须先查看管理器、Python 版本、包、Kernel 与清理步骤，再输入精确确认短语。
- 最小环境固定安装 Jupyter Server、ipykernel、NumPy、Matplotlib 与 Pillow；不自动读取或安装 Workspace 依赖，也不隐式加入 PyTorch、Transformers 或 CUDA。
- 只有环境创建、依赖安装、Kernel 注册和 Python 复检全部成功后才写 ready marker；取消或失败会杀掉当前子进程并删除未完成目录。
- TensorNote 可在随机 Loopback 端口启动带 256-bit Token 的 Owned Jupyter，等待就绪后生成会话 Compute Profile；提供脱敏日志与停止操作，退出应用时清理 Owned Server。
- Static Web 构建不包含 Local Runtime Assistant 或 `local_runtime_*` IPC；Web 用户继续手动连接自己的本地或 HTTPS Jupyter。

## 安全边界

- 不开放 Shell 插件、通用命令、前端可控的可执行路径、目标路径或任意参数。
- 环境创建只能写入 TensorNote 应用数据目录中的 Managed Environment；Kernel Spec 使用环境本地 prefix。
- Jupyter 只绑定 `127.0.0.1`，Origin 限制为受信任 Desktop/Local Dev Origin；Token 只存于 Rust 内存和前端 `sessionStorage`。
- Stop 只接受当前进程内所有权表中的 Opaque Server ID，不会扫描、接管或终止外部 Jupyter。
- 日志最多保留 500 行，并替换 Token、应用数据目录、Workspace root 与用户 Home。

## 当前限制

- 本阶段不安装 GPU/ML 框架、不解析 Workspace requirements 作为安装授权，也不提供任意包管理器 UI。
- 不接管已经运行的外部 Server；检测到的外部 Loopback Server 只用于可见性，连接仍使用手动 Compute Profile。
- 当前安装资产未签名、公证或发布；本阶段不创建 Tag/Release。
